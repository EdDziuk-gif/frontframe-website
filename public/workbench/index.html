The assistant represents organizational knowledge to public and internal users. The surrounding system supplies bounded agents, application logic, stores, authority rules, and escalation paths rather than treating the assistant as one unconstrained intelligent object.

An FF agent is provisionally described by its purpose, scope, and required operational behaviors. Governance is not embedded in those behaviors; the Constitution regulates their exercise.

Agents perform specialized bounded functions. Human operators/delegates retain judgment and authority for organizational commitments, promulgation, constitutional amendment, and other governed decisions.

Operational: a valid rule already covers the situation. Constitutional: no valid rule covers the case, authorities conflict, or resolution requires creating/changing governing authority.

SCR evaluates whether candidate content is responsive and resolving for the expressed demand. It does not certify factual correctness.

SCA routes to insufficient, limited, or strong-confidence handling.

KGR remains authorization-gated and manually bootstrapped until real cases demonstrate what should be automated.

A question produces candidate content. SCR scores appropriateness. SCA routes according to the organization's thresholds. Strong confidence is delivered normally; limited confidence is hedged; insufficient confidence routes toward gap resolution.

Candidate material becomes usable organizational knowledge only after authorized human sign-off.

  • Kill switch: implemented by extending config.mode with a disabled state. The chat handler checks that state immediately after loading config, before Supabase content lookup or any Anthropic API call, and the existing admin Config mode dropdown exposes the state with a warning banner.
  • Rate guard: KV-backed protection implemented and live; current limits are provisional pending real traffic evidence.
  • resolve_gap visitor fallback: copy and insertion point established; intentionally not wired ahead of the scoring system.

Gate passed: Phase A was functionally smoke-tested in production and the repository and deployed state were reconciled.

Known follow-up: the second Cloudflare dashboard rate-limiting layer remains deferred. The current KV limits should be revisited when actual traffic provides evidence for tuning.
